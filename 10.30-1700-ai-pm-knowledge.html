01 / LLM fundamentals

How an LLM actually works

A large language model is a neural network—usually a transformer—trained to predict the next token in a sequence. Text is tokenized, converted into vectors, processed through layers of attention and feed-forward networks, and used to produce a probability distribution over the next token. Generation repeats until a stopping condition is reached.

Tokens

Units of text processed by the model. A token may be a word, part of a word, punctuation, or whitespace.

Embeddings

Dense numerical vectors representing tokens or other content in a learned semantic space.

Attention

Lets each token incorporate information from other relevant tokens in the context.

Model weights

Learned numerical parameters encoding patterns acquired during training. They are not a searchable store of facts.

Context window

The maximum input and generated content considered in one request. Beyond it, content must be omitted, compressed, or selectively retrieved.

Next-token prediction

The model predicts a distribution for the next token; decoding selects or samples one, appends it, and repeats.

Pre-training versus post-training

  • Pre-training: Learns broad language and world-pattern representations from large datasets, commonly using next-token prediction.
  • Post-training: Shapes the pretrained model for useful behavior through supervised fine-tuning, preference optimization, and safety training.
  • Fine-tuning: Further trains weights on a targeted dataset or task. It changes behavior; it is not the same as supplying live facts.
  • Prompting: Changes instructions and context without changing model weights.

What does temperature control?

Temperature changes the sharpness of the token probability distribution during sampling. Lower values make high-probability tokens more dominant; higher values increase variety and unpredictability. Temperature 0 is typically close to greedy decoding, although implementation details matter. Temperature does not make a model more knowledgeable.

Why do models hallucinate?

A model is optimized to generate plausible continuations, not guarantee truth. It can lack knowledge, misread context, rely on weak patterns, or confidently fill gaps.

PM response: Ground answers in trusted sources, constrain tasks, expose uncertainty, validate important claims, and provide abstention or escalation paths. Measure factuality and impact in real usage.

Why isn't an LLM a database?

A database stores and retrieves records with explicit schemas and query semantics. Model weights encode statistical patterns, not a reliable, current, row-addressable source of truth. Use databases for authoritative records; use retrieval or tools to bring relevant data into a model request.

Why can identical prompts produce different answers?

Sampling, nondeterministic hardware execution, serving infrastructure, model/version changes, hidden system context, and tool results can affect outputs. Reproducibility requires controlling variables and recording model and configuration versions.

02 / Tools, agents & MCP

How tool and function calling works

A model generally does not execute an external function itself. It emits a structured tool request; the application validates and authorizes it, executes the function, and returns the result to the model.

  1. The application sends messages and available tool definitions to the model.
  2. The model requests a tool with a name and structured arguments.
  3. The orchestrator validates arguments, permissions, and policy.
  4. The application executes the tool and returns its output.
  5. The model interprets the result or requests another tool.

What makes a good tool definition?

A tool definition usually includes a name, natural-language description, and input schema. The description helps the model decide when to use it; the schema constrains arguments. Vague descriptions, overlapping tools, or permissive schemas reduce reliability.

Prompt versus tool versus skill

  • Prompt: Instructions and context for a model invocation.
  • Tool: A callable capability that performs an action or retrieves information.
  • Skill: Reusable domain instructions, procedures, and supporting knowledge that guide how work is performed.

What makes an agent different from a chatbot?

A chatbot primarily responds to user turns. An agent can pursue a goal over multiple steps, maintain state, choose tools, observe results, recover from failures, and decide when the task is complete. Adding a tool call alone does not necessarily make a system meaningfully agentic.

What does agent memory mean?

Memory may include short-lived conversation state, persistent preferences, task state, or an external knowledge store. Decide what is remembered, for how long, how it can be corrected or deleted, and what permissions govern its use. The context window is not durable memory.

What is MCP?

The Model Context Protocol (MCP) is an open protocol for connecting AI applications to external tools and context providers through a standardized interface. It can reduce bespoke integration work, but does not remove the need for authentication, authorization, validation, observability, versioning, and security review. Compare MCP with one-off APIs based on reuse, interoperability, overhead, and control.

03 / RAG & context engineering

Walk through a RAG pipeline

Retrieval-augmented generation retrieves relevant external information and supplies it to the model as context, helping it answer using private, changing, or otherwise unavailable data.

  1. Ingest: Connect to source systems and extract documents.
  2. Prepare: Clean, normalize, and enrich content with metadata and access controls.
  3. Chunk: Divide content into passages while preserving semantic boundaries.
  4. Embed and index: Convert chunks into vectors and store them with metadata.
  5. Retrieve: Find candidates using vector, keyword, or hybrid search.
  6. Rerank and filter: Improve relevance, apply permissions, and remove unsuitable results.
  7. Assemble context: Select passages and citations within the token budget.
  8. Generate: Ask the model to answer using the evidence.
  9. Evaluate: Measure retrieval quality, groundedness, latency, cost, and user outcomes.

RAG versus fine-tuning versus prompting

ApproachBest suited forMain limitation
PromptingInstructions, formatting, examples, task framingDoes not reliably add large or changing knowledge
RAGCurrent, private, source-grounded informationRetrieval can miss or mis-rank evidence
Fine-tuningConsistent behavior, style, task patterns, formatsUpdating facts is costly; facts may not be reliably retrievable

These approaches can be combined: fine-tune a format, retrieve current policies, and prompt for the task.

Vector databases and embeddings

A vector database stores embeddings and supports similarity search. It is useful when semantic similarity matters, but keyword search is often better for exact identifiers, names, and codes. Hybrid search combines strengths.

Chunking: what matters?

Chunk size and overlap influence retrieval precision, context cost, and whether a passage retains enough meaning. Chunk by document structure where possible; preserve titles, headings, source IDs, timestamps, and access metadata. Evaluate choices against representative queries.

How do you handle frequently changing information?

Use authoritative connectors, incremental ingestion, freshness metadata, deletion propagation, and cache invalidation. For rapidly changing or transactional facts, call the source system at request time rather than relying only on an asynchronously refreshed index.

Two broad RAG failure modes

  • Retrieval failure: Relevant evidence is not found or is ranked too low.
  • Generation/grounding failure: Evidence is retrieved, but the model misinterprets it, ignores it, or makes unsupported claims.

Diagnose these separately. A better model will not fix broken retrieval, and better retrieval will not guarantee faithful generation.

Context engineering versus prompt engineering

Prompt engineering focuses on instruction wording. Context engineering designs all information supplied to the model: system instructions, conversation state, retrieved evidence, tool outputs, memory, ordering, metadata, and token allocation.

When is RAG overkill?

RAG may be unnecessary when facts are few and stable, a deterministic API can answer directly, the model already has sufficient general knowledge, or complexity outweighs value. Prefer the simplest architecture that meets accuracy, freshness, privacy, and latency requirements.

04 / Orchestration & routing

What is orchestration?

Orchestration coordinates models, tools, data, and workflow steps. It manages sequencing, state, retries, timeouts, branching, permissions, and failure handling.

LangChain versus LangGraph

LangChain provides abstractions and integrations for LLM applications. LangGraph focuses on stateful, graph-based orchestration, including cycles and controlled agent workflows. Choose based on workflow complexity and required control—not popularity.

Raw SDK versus framework

A raw SDK call can be simpler, transparent, and easier to optimize for a small workflow. A framework helps when integrations, state, branching, or reusable orchestration become substantial. Abstraction adds value only when it reduces total complexity.

What is model routing?

A router selects a model or execution path based on task complexity, modality, latency target, cost budget, privacy constraints, and quality requirements. It may use a classifier, explicit rules, confidence, and fallback paths.

How does routing affect unit economics?

At high call volumes, small per-request cost differences compound. Measure total cost per successful task, not just token cost. Include retries, tools, retrieval, guardrails, evaluation, caching, and human review. Cheaper routing is useful only if quality and completion remain acceptable.

Four useful layers of an AI product stack

1. Experience

User interface, workflow, and feedback.

2. Orchestration

Prompts, context assembly, routing, tools, and agent control.

3. Intelligence

Models, embeddings, rerankers, and evaluation models.

4. Data & infrastructure

Sources, indexes, storage, compute, security, and observability.

This is a practical mental model, not a universal standard.

How do you sequence multiple agents?

Use multiple agents when roles require distinct context, permissions, tools, or independently verifiable responsibilities. Define ownership, hand-offs, shared state, termination, and conflict resolution. Parallel agents can increase latency, cost, and coordination failures.

05 / System design & trade-offs

Design an AI feature: summarize unread messages

Start with the user problem: help someone catch up quickly without missing important information. Define user, message sources, freshness, and what makes a summary useful.

  • Permission-aware message retrieval.
  • Prioritization of relevant unread messages.
  • Summarization with citations or links to source messages.
  • UI distinguishing facts, inferred themes, and suggested actions.
  • Feedback controls and access to original messages.

Measure time saved, useful coverage, factuality, trust, and follow-through—not summary length. Test long threads, conflicting messages, attachments, and access changes.

Latency versus quality versus cost

These objectives compete. Larger models and more retrieval or reasoning steps may improve quality but increase cost and latency. Set a quality threshold, then optimize with routing, caching, smaller models, parallelism, shorter context, and selective tool use. Track p50/p95 latency, cost per successful task, and quality together.

Build versus buy versus fine-tune

  • Buy/use a hosted model: Fastest path; assess data handling, reliability, cost, customization, and vendor dependency.
  • Build/self-host: More deployment, data, and optimization control; requires serving expertise and infrastructure operations.
  • Fine-tune: Consider when repeatable behavior cannot be achieved economically with prompting and retrieval. It is not the default way to keep facts current.

Why not use an LLM for everything?

LLMs are probabilistic and can be expensive, slow, and difficult to validate. Use deterministic code, databases, rules, and conventional ML when they solve the problem more reliably. Hybrid systems often offer the best experience.

Why XGBoost over an LLM for tabular prediction?

For structured, labeled tabular data, gradient-boosted trees such as XGBoost can be more accurate, cheaper, faster, and easier to evaluate than a general-purpose LLM. Use an LLM when language understanding, unstructured context, or natural-language interaction is central.

What does a hybrid AI system look like?

A hybrid system combines deterministic software, conventional ML, LLMs, retrieval, and human judgment. For example, rules enforce eligibility, a classifier prioritizes cases, an LLM summarizes evidence, and a human approves high-impact decisions.

What role do GPUs play in cost?

GPU cost depends on accelerator type/count, memory capacity and bandwidth, utilization, model size, sequence length, batching, parallelism, serving overhead, power, networking, and availability. For inference, distinguish prefill (processing input tokens) from decode (generating output tokens). Capacity planning should model traffic shape and latency SLOs, not just average tokens per day.

Estimate inference cost for 10 million users

Do not estimate from user count alone. Model active users per day, requests per user, input/output tokens, peak concurrency, model mix, routing, caching, retries, tool calls, throughput per accelerator at target latency, replication, and utilization headroom. Estimate accelerator-hours and multiply by fully loaded cost per accelerator-hour. Validate with production-like benchmarks; theoretical peak FLOPs are not serving throughput.

How do you design for failure?

Plan for tool timeouts, rate limits, malformed outputs, unavailable models, retrieval outages, stale data, and partial completion. Use bounded retries with backoff, idempotency, circuit breakers, fallbacks, clear messaging, and human escalation for consequential workflows.

Where do you draw safety redlines?

Define prohibited actions, allowed data, consent, permission checks, human approval thresholds, and escalation. Enforce critical controls in application code and tool permissions—not only prompts. Test prompt injection, data leakage, adversarial inputs, and unsafe tool use.

Models improve monthly. What stays constant?

Model capabilities and prices change quickly. Durable product work includes customer understanding, workflow integration, data quality and rights, trust, evaluation, security, distribution, reliability, and measurable outcomes. Keep architecture modular enough to change models without rebuilding the product.

06 / Evals & metrics

Build an evaluation framework from scratch

  1. Define the user outcome and failure costs.
  2. Identify representative tasks and segment by risk and difficulty.
  3. Create a versioned dataset of realistic inputs and expected properties.
  4. Define rubrics for correctness, relevance, completeness, groundedness, safety, and style.
  5. Combine deterministic checks, human review, and model-assisted evaluation.
  6. Establish baselines and release thresholds.
  7. Run offline evaluations, then shadow or limited production tests.
  8. Monitor real-world quality, regressions, and user feedback continuously.

Precision, recall, and F1

  • Precision: Of the items predicted positive, how many were actually positive?
  • Recall: Of all actual positive items, how many did the system find?
  • F1: The harmonic mean of precision and recall.

Use precision when false positives are costly; use recall when missing a relevant item is costly. Explain the trade-off in terms of user impact.

What is LLM-as-judge?

An LLM judge scores outputs against a rubric. It can scale evaluation, but may be biased by wording, verbosity, position, or model preferences. Validate it against human judgments, use clear rubrics and blind comparisons where possible, and audit disagreement. Do not use it as the sole authority for high-stakes decisions.

How do you evaluate a non-deterministic system?

Use repeated runs, distributions, confidence intervals, and task-level pass rates rather than expecting identical outputs. Track performance by scenario and segment. Preserve test inputs, model versions, prompts, tool versions, and evaluation configuration to diagnose regressions.

Testing pyramid for AI products

  • Unit tests: Deterministic code, schemas, permissions, parsing, and policy enforcement.
  • Component tests: Retrieval, tools, prompt assembly, and model adapters.
  • Evaluation tests: Golden datasets, adversarial cases, and repeated model runs.
  • End-to-end tests: Full user workflows with real or representative dependencies.
  • Production monitoring: Quality signals, user feedback, latency, cost, and incidents.

How do you catch regressions after a model swap?

A model swap can change formatting, tool selection, refusal behavior, latency, cost, and factuality. Run the same versioned evaluation suite against old and new models, compare by task segment, and use shadow traffic or a gradual rollout with rollback criteria.

What is observability for AI products?

Capture traces across the request: model/version, prompt template version, token counts, retrieval sources and scores, tool calls, latency, retries, errors, cost, and user feedback. Redact or minimize sensitive content and enforce access controls and retention policies.

How would you design a human-in-the-loop feedback system?

Collect explicit ratings and corrections, plus behavioral signals such as edits, retries, abandonment, overrides, and acceptance. Connect feedback to a failure category, workflow stage, and evaluation case. Protect privacy and avoid treating every user action as ground truth.

Offline evals pass but users are unhappy. What now?

Check whether the evaluation set represents real users, workflows, and edge cases. Investigate usability, trust, latency, freshness, coverage, discoverability, and whether the feature solves the actual problem. Segment feedback; averages can hide poor experiences for important cohorts.

Faithfulness versus retrieval quality

Retrieval quality asks whether the right evidence was found. Faithfulness asks whether the generated answer accurately reflects that evidence. Measure separately: retrieval metrics can include recall@k and ranking quality; generation metrics can include claim support, citation correctness, and unsupported-claim rate.

What should you check first when quality drops?

Check recent changes in model/version, prompt, retrieval index, source data, tool behavior, traffic mix, and evaluation configuration. Use traces and segment-level metrics to isolate the stage and cohort affected before changing the model.

  2. Define success metrics and unacceptable failure modes.

  5. Cover latency, cost, reliability, privacy, and safety.
  6. Explain evaluation, launch strategy, and iteration.

08 / The technical AI PM answer framework

For almost any technical AI PM question, structure the answer around these lenses:

01 · User problem

Who is the user, what job are they trying to do, and why is AI useful?

02 · Mechanism

What happens under the hood, from input to output?

03 · Alternatives

Could rules, search, conventional ML, or a smaller model do the job?

04 · Trade-offs

What are the implications for quality, latency, cost, privacy, and complexity?

05 · Failure modes

How can the system fail, and how will users recover?

06 · Evaluation

How will you know it works across realistic scenarios?

07 · Operations

How will you monitor, secure, scale, and improve it?

08 · Business outcome

What measurable customer or business value does it create?

The strongest PM answers connect technical depth to product judgment. Avoid naming technologies without explaining why they fit the problem and what you would measure.

Quick glossary

GroundingTying an answer to trusted evidence or data.
HallucinationA plausible-sounding but unsupported or incorrect model output.
InferenceRunning a trained model to produce outputs.
PrefillProcessing the input sequence before token generation.
DecodeGenerating output tokens sequentially.
RerankingReordering retrieved candidates using a relevance model.
RedlineA defined boundary beyond which a model or feature must not operate or be released.
SLOA target for a service-level indicator, such as latency or availability.
Non-determinismVariation in outputs or execution despite apparently identical inputs.
